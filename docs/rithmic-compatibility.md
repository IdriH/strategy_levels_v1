## Volume profile correction

The former check required `sum(VolumeAnalysisData.PriceLevels[*].Volume) == HistoryItemBar.Volume`. Quantower documents [`VolumeAnalysisData.Total.Volume` as the aggregated volume-analysis value and `PriceLevels` as the same metrics per price](https://help.quantower.com/quantower/quantower-algo/access-volume-analysis-data-from-indicators). The [VolumeAnalysisData API](https://api.quantower.com/docs/TradingPlatform.BusinessLayer.VolumeAnalysisData.html) exposes these together. The candle volume is a separate field; the cited API does not guarantee equality across the two streams. The screenshot identifies this old cross-field comparison as the rejection site. The exact live difference/ratio is unknown.

The corrected provider conserves each minute's supplied levels against its native `Total.Volume`, retains unmodified price/volume bins, and reports candle/native differences as diagnostics. Source connection/contract/tick, advertised native M1 capability, completed bounded RTH interval, every expected minute, valid prices within Last-bar bounds, nonnegative native volume and native conservation remain required. Null data stays missing. An explicit native zero conflicts with a known positive candle volume. No factor-of-two conversion, synthetic allocation, or partial-profile acceptance is introduced.

The request uses `CalculatePriceLevels=true`, `ForceUsingTickData=false`, `FilteredVolume=0`, source tick size and step one. The [calculation parameter API](https://api.quantower.com/docs/TradingPlatform.BusinessLayer.VolumeAnalysisCalculationParameters.html) supports those fields, and Quantower describes its [dedicated Rithmic volume-analysis loading mechanism](https://www.quantower.com/blog/connection-to-deribit-improvements-for-dom-trader-and-option-analystics-panels). This preserves the earlier fix for the connector's tick-history reconstruction refusal.

## Options correction

The official [Quantower options example](https://github.com/Quantower/Examples/blob/master/IndicatorExamples/GetOptionsInfo.cs) obtains series for a source symbol and then strikes for a particular series. The installed SDK's explicit request overloads preserve that workflow while adding cancellation, selected connection, exact source underlying and series ID. [Quantower's Rithmic connection guide](https://help.quantower.com/quantower/connections/connection-to-rithmic) documents futures and options connectivity; [Rithmic's own exchange/data reference](https://www.rithmic.com/platforms/exchanges) lists CME futures/options on futures and distinct historical tick, time-bar and aggregated data formats. These are capability statements, not account entitlement or timestamp-precision guarantees.

The old child verifier required literal IDs in all populated underlying fields, identical option/series expiration timestamps, and fully populated child `OptionSerie` fields. The [Symbol API](https://api.quantower.com/docs/TradingPlatform.BusinessLayer.Symbol.html) exposes these fields but does not guarantee the same expiry precision or that every optional child field is populated. Cached SDK underlying/series getters are backing-field reads, as established by static IL inspection; they do not independently establish alias semantics. The screenshot cannot identify which predicate rejected the 1,714 rows.

The corrected adapter resolves underlying aliases on the same connection and verifies full exact-contract metadata. Missing child fields can inherit a verified exact-series request's context. Populated conflicts remain rejected. Calendar-style midnight expiry metadata can agree with an actual supplied same-series/date timestamp; precise timestamps must still match each other. Original dates survive UTC normalization, unknown current-day cutoffs remain conservative, and up to eight uncertain current-date series are queried without displacing the configured future series. The final selector applies the configured nearest-series and strike limits. Status reports rejection reasons and any inherited metadata through subsequent source-price reselection. OI and option volume validity/publication limitations are unchanged.

[Quantower release notes](https://www.quantower.com/release-notes) list installed 1.146.18 as stable (7 August 2026), and a possible Rithmic option-series duplication correction in 1.147.5 beta (28 September 2026). Distinct series IDs therefore remain distinct even when expiry dates match. No terminal upgrade is required or performed by this change.
