# Quantower chart validation

Build/install from the README and add **NQZ6 Candidate Levels**. These checks require the terminal and an active Rithmic session; they have not been executed by the offline test suite.

1. **Resolution:** Select the Rithmic connection ID. Confirm the panel source name and logged contract ID, December 2026 metadata, 0.25 tick and correct connection. Try MNQ/another expiry as the explicit source contract ID: resolution must fail with no active candidates. With two active Rithmic connections and a blank selector, selection must be required. Clear the exact ID for automatic resolution only after loading NQZ6 into platform lookup.
2. **History:** Confirm loading finishes and the initial M1 time range covers the expected lookback. Inspect provider health for missing-minute counts or missing starts. Missing data must suppress affected levels without zero-price references. Compare previous RTH/full, overnight, week and OR values with independently inspected NQZ6 Last/M1 observations using the calendar's UTC windows.
3. **Source independence:** Attach instances with identical settings to NQZ6 M1, M5 and H1 charts. Pause or capture the same **observed source as-of timestamp** and compare all raw prices/IDs. Computed-at times and instance version numbers can differ. Attach to ES, MNQ and an option chart with a different aggregation; at the same source as-of time the NQZ6 values remain identical. Confirm the badge/table appear and out-of-scale prices do not force the host scale. A quiet host symbol must not stop NQZ6 updates.
4. **Timing:** Before the first 15 cash minutes complete, final OR is absent. With developing OR enabled, it is labelled developing. After completion, OR freezes. Overnight freezes at cash open. RTH references roll once source observations reach cash end; full references roll once source observations reach futures end. Confirmed swings first appear after the right completed bars and begin at confirmation. Scroll left before known-at: current-version weekly/VWAP/options values must not be painted earlier.
5. **Permissions:** Record one snapshot, switch Both/BuyOnly/SellOnly/NoTrade. Above/below source price drives buy/sell geometry regardless of the reference name. NoTrade has zero active candidates. Unfiltered references retain prices and provenance; disallowed/context lines are grey if shown. Bias/style changes should not launch a new history download.
6. **Optional data:** With options enabled, confirm verified underlying/connection and nearest-series/strike counts. Missing permissions or unverifiable chain gives a readable status while price providers remain usable. OI publication times remain unknown; no fabricated zero OI. Enable profile separately and verify complete minute/real price-level coverage, POC/tie rule and node parameters. On Rithmic, confirm the former "Volume analysis calculation from ticks history is not allowed" warning does not appear: the updated provider permits the SDK's native path instead of forcing ticks. Compare the same previous RTH and one-tick bin width with a native NQZ6 volume profile; reconcile exact source window, traded-volume totals and deterministic POC ties. A feed without price-level history must report unavailable rather than generate a profile from OHLCV volume.
7. **Corrections:** If the feed offers corrected history or a controlled local adapter fixture, verify M1 timestamp replacement, no duplicate volume, new snapshot version/Corrected quality, and receipt known-at for revised values. A changed profiled RTH bar must invalidate and refresh the profile. Recheck cached strikes after source price moves without repeated chain downloads.
8. **Health:** Disconnect Rithmic: candidates must become inactive within the timer interval. Reconnect: history reloads and outdated callbacks cannot replace the new snapshot. During the 16:00–17:00 Chicago break/weekend, status says market closed; a stale open-market feed is distinguished. A missing/malformed calendar file or uncertain special date must suppress affected calculations. At the NQZ6 termination cutoff, all directional activity stops without rollover.
9. **Cleanup:** Note terminal subscription/resource counts where available. Remove/re-add, change settings, reload chart history and change host symbol/timeframe several times. Expect one owned Last/M1 history and one Last handler per live instance, no callbacks from removed instances, no repeating old requests and no persistent growth after removals. Platform-owned symbols/graphics remain usable by other indicators.
10. **Layout:** Zoom, scroll and resize the main pane. Rays must clip, right labels must avoid overlap, and the table must retain NQ prices on different instruments. Increase table rows or enlarge the pane to inspect all merged levels; reduce font/detailed health on compact charts. Check the table as-of and known-at times when comparing snapshots.

Record SDK version, connection identifier without credentials, tested source contract ID, source as-of timestamps, provider statuses and any feed omissions. Do not describe runtime checks as passed merely because the build or pure tests passed.

For the 8 October compatibility update, inspect option exclusion reason counts and inherited series-metadata counts rather than the former generic rejection. Test an expiration day with a supplied intraday cutoff and verify unknown date-only cutoffs remain excluded. For profiles, compare raw native session volume with `VolumeAnalysisData.Total.Volume`, preserving any displayed OHLCV/native discrepancy; compare POC using identical previous-RTH boundaries and one-tick bins. A true native level/total mismatch must still show the affected minute and both volumes. The [investigation](rithmic-compatibility.md) contains the exact field semantics and official references.
